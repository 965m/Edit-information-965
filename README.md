# いい曲の条件(授業用ウェブサイト)

文章・色・動き・グラフ・ページの並びを、ファイルを書き換えるだけで変えられる作りです。
`index.html` をブラウザで開くか、GitHub Pages などに置けば動きます。

## 操作
- 最初の画面は自動では始まりません。「はじめる」ボタンを押すとスタートします(始まったあとは、画面のどこをクリックしても次へ進みます)。
- 最後のページ(結果)に着くまで、縦スクロールはできません(右上の「最後へ」で飛んだ場合も、着いた時点で解除されます)。
- 放置リセット: 何も操作しないまま `idle.seconds` 秒(初期90秒)たつと、最初の画面に戻ります。ON/OFFはページの一番下の右下のスイッチで切り替えられます(閲覧した人のブラウザに記憶)。初期状態は `config.js` の `idle.enabled`。
- 画面のどこをクリックしても、すぐ次のページに進みます(右上の「最後へ」で最後の場面まで一気に飛べます)。
- 円グラフが開く動きの途中でクリックすると、すぐに開いた状態(結果)になります。
- 開いた状態では自動で進みません。もう一度クリックすると次のページへ進みます。
- 聴く量を選ぶページと、最後の結果ページは、選ぶまで(ボタン以外のクリックでは)進みません。

## どこを触ればいいか

| やりたいこと | 触るファイル |
| --- | --- |
| ページの並び・追加・削除、回答シートの設定 | `js/config.js` |
| 文章、インタビュー、おすすめ曲、各要素の説明、文章だけのページ | `js/content.js` |
| 色・フォント | `css/theme.css` |
| 回答が足りない間に出す仮のデータ | `js/sample-data.js` |
| ページ(場面)ごとの見た目と動き | `js/scenes/` の各ファイル |
| 仕組みそのもの(ふつうは触らない) | `js/core/` `js/flow.js` `js/main.js` |

## 回答データの仕組み(結果が自動で変わる)

`js/config.js` の `source.sheetId` に、フォームの回答スプレッドシートのIDが入っています。
サイトを開くたびに(そして `refreshSeconds` 秒ごとに)回答を読み込み、次のものを自動で集計します。

- 一番重視する要素 → 円グラフ、順位、上位の切り抜きと展開、縦スクロールの説明
- 聴く時間 → 相関グラフ(5段階に分けて比較)
- 一番以外に重視する要素 → 各要素の「ほかに大事にしていること」
- 苦手な要素・苦手な曲の例 → 「これは苦手」のランキングと例
- よく聴くジャンル・アーティスト・好きな曲(リンク) → 各要素の説明と、おすすめ曲(回答者のおすすめ)
- 聴く時間のランキング・よく使うプラットフォームのランキング・新しい曲探し/歌なしの曲 → 「みんなの聴き方」ページ(`habits`。横スクロールにも縦スクロールにも出ます)。
  それぞれ「聴く量との相関(r)」と平均の聴く量を併記します
- アンケート → 下の「アンケート画面」
- 苦手な要素(Q4) → 「重視する要素ごと」の説明に、その要素を選んだ人が挙げた苦手な要素を表示(全体のランキングも従来どおり)
- 好きな曲のリンク(Q14) → 曲名とアーティスト名を調べて、各要素の「好きな曲」「よく聴くアーティスト」とおすすめ曲に反映
- 苦手な楽曲の例(Q5) → リンクなら曲名とアーティスト名を調べて記録。文字なら iTunes で検索して、見つかった時だけ記録(見つからなければ反映しない)。要素ごと・全体の「苦手な曲の例」に表示
- そう思った理由やコメント → 重視している要素ごとに、その要素を選んだ人のコメントを順番に切り替えて表示(上位3つの切り抜きカードと、縦スクロールの説明の両方)。1件だけなら切り替えません。回答が10人に満たない間は、`content.js` の各要素の `quotes` を表示します
- よく聴くアーティスト(Q12) → 要素ごとと、全体の「よく聴かれているアーティスト」に表示

**回答が10人に満たない間は仮のデータで表示**します(右上に「回答 ○/10人・仮データ表示」と出ます)。
人数は `source.minResponses` で変えられます。

### つながらない時
- シートの共有を「リンクを知っている全員が閲覧可」にしてください。
- それでも読めない時は、右上に「読み込めず・仮データ表示」と出ます。GAS を使う方法に切り替えられます(下記)。
- フォームの選択肢が `content.js` に無い要素でも、回答に出てきた言葉で自動的に円グラフの1切れになります
  (説明文は回答から作った簡易な文になります。`content.js` に同じ名前の要素を足すと、好きな説明を書けます)。

### 聴く時間を5段階にする
今のフォームの8つの選択肢は、`config.js` の `levelMap` で5段階に対応づけてあります(「～2時間」と「～3時間」は4、「～4時間」以上は5、「平日は聴かない」は1)。
フォームの選択肢を変えたら、ここも直してください。短い順に並べるだけでよければ `timeOptions` でも指定できます。

```js
timeOptions: ['30分未満', '30分〜1時間', '1〜2時間', '2〜3時間', '3時間以上'],
```

書かない場合は、選択肢の文字の中の「1時間」「30分」などの数字から自動で判断します。

### GASで読む場合(任意)
読み込めない時のチェック: ①`gasUrl` は「デプロイ → 新しいデプロイ → ウェブアプリ」の **`…/exec`** で終わるURL ②「次のユーザーとして実行」=自分、「アクセスできるユーザー」=**全員** ③`Code.gs` を直したら必ず「新しいデプロイ」(古いURLは古いコードのまま)。GASから読めない時は、自動でシートを直接読む方法に切り替わります(右上の表示にマウスを乗せると原因が出ます)。

1. 回答のスプレッドシート → 拡張機能 → Apps Script に `gas/Code.gs` を貼って保存
2. デプロイ → 新しいデプロイ → ウェブアプリ(実行: 自分 / アクセス: 全員)
3. 出てきたURLを `config.js` の `source.gasUrl` に貼る

## コメントの切り替え表示(秒数・動きの変更)
`js/config.js` の `comments` で変えられます。

| 設定 | 内容 |
| --- | --- |
| `intervalMs` | 次のコメントに切り替わるまでの時間(初期 2000 = 2秒) |
| `transitionMs` | 切り替えアニメーションの長さ(初期 900) |
| `animation` | `'lines'`(初期値。線の幕が走って入れ替わり、カードの外周を線がなぞる) / `'slide'`(下から) / `'flip'`(めくる) / `'wipe'`(線が走る) / `'fade'` |
| `max` / `maxLength` | 1要素あたりのコメント数の上限 / 長いコメントを省略する文字数 |
| `showName` | コメントの下にシートの「名前」を表示(`false` で非表示) |
| `showTime` | コメントの下に「1日 ～1時間程度」のようにシートの聴取時間を表示(`false` で非表示) |
| `pauseOnHover` | `true` で、マウスをカードの上で動かしている間は切り替えを止める(初期値は `false`) |

下の細い線は、次に切り替わるまでの残り時間を表します。フォームの列は、見出しに「そう思った理由」か「理由やコメント」が入っている列を使います(`config.js` の `columns.comment`)。

## 導入の文章(「はじめる」のあと)
- 文章は `js/content.js` の **`prologue`** に書きます(`lines` に1行ずつ。`**こう書く**` で強調)。1ブロックが1画面で、順番に切り替わります。1画面の文字が `maxChars` を超えると、行ごとに自動で次の画面に分かれます。
- 読む時間は `baseMs + 文字数 × perCharMs`(最短 `minMs`)で自動計算され、たつと次のページへ進みます。画面をクリックすると、すぐ次の文章/ページへ進みます。
- `motion` で背景の動きを選べます: `staff`(五線を点が流れる) / `ring`(円グラフが描かれる) / `ripple`(波紋)。場面そのものは `js/scenes/prologue.js`、`config.js` の `sceneOrder` の `'prologue'`(消すと外せます)。

## 画面まわりのメモ(最新)
- **「聴く量で重視する要素が変わるか」の次のページ**(`js/scenes/corrtop.js`): 関係が最も強かった要素を1つ取り上げて、文章と軽い棒グラフで紹介します。表示時間は `config.js` の `timing.corrTopMs`。並びは `sceneOrder` の `'corrTop'`(消すと外れます)。
- **聴き方のクセ**: 「重視する要素との相関」を大きく、はい/いいえの割合は細い帯で小さく表示します。
- **仮データ ⇔ 回答データの切り替え**: 縦スクロールの一番下(右下)、「放置で最初に戻る」のとなりにスイッチがあります。ONで仮のデータ、OFFで回答データ(10人以上集まっている時)。選んだ状態はその人のブラウザに記憶されます。
- **縦スクロールの「みんなが重視した要素」**: 円グラフ(または右の順位表)をクリックした時だけ、その項目の説明がすぐ下に出ます(ページが長くなりません)。「円グラフにもどる」か、ボタン以外の場所をクリックすると閉じて円グラフに戻ります。
- **画面の上下のゆれ**: 曲の照合が1件終わるたびに画面を描き直していたのが原因でした。中身が変わった時だけ描き直し、描き直してもスクロール位置を保つようにしました。

## おすすめ曲の再生ボタン(▶)
- 「おすすめを聞かれたら」やドロワーの曲に ▶ があります。同時に流れるのは1曲だけで、もう一度押すと止まります。
- **サビから流す**には、`recommend.js`(またはシートの「おすすめ曲」タブ)で、曲に **YouTubeのリンク** と **サビの開始(秒、または 1:15)** を書きます。その秒数から、小さなYouTubeプレーヤーで流れます。
- 設定がない曲は、**iTunesの30秒試聴**が流れます。曲の聴きどころが選ばれることが多いですが、「サビから」とは限りません(サビの位置を自動で見つけることはできません)。iTunesに無い曲は ▶ が × になります。

## おすすめ曲の設定(聴き方ごと・質問ごと)
**編集する場所: `js/recommend.js`(曲はすべてここ。以前 `content.js` にあった曲も移しました)**。
- **`js/recommend.js`** を開いて、1行1曲で足すだけです: `['歌詞', 3, '曲名', 'アーティスト', 'ひとこと', 'リンク', '質問']`(リンクと質問は省略可)。聴く量は 1(あまり聴かない)〜5(とても聴く)。
- **質問**に「おすすめを聞かれたら」の質問文(`content.js` の `askTips` の `q`)を書くと、その質問をクリックした時に右に出る曲になります。空欄なら、その要素のおすすめ全部(回答者の好きな曲を含む)が出ます。
- **スプレッドシートで管理する場合**: 同じシートに「おすすめ曲」タブを作り(見出し: 要素 / 聴く量 / 曲名 / アーティスト / ひとこと / リンク / 質問)、そのタブの gid を `config.js` の `source.recommendGid` に入れます。タブに書いた曲はサイトを開き直す(または自動更新)だけで反映され、`recommend.js` の曲に足されます。
- 結果ページの「あなたの聴き方」ドロワーにも、同じおすすめが出ます。

## 苦手な要素のまとめ(AI)と、クリックで曲の例
- 「これは苦手、と言われたこと」の要素をクリックすると、右に**その要素が苦手と答えた人があげた苦手な曲の例**(リンク・曲名から見つかったもの)が出ます。
- 似た内容のまとめ(例: 声が高い / 高音 / キンキンした声 → 高い声)は、GASを使っていると**AIが自動でまとめます**。仕組み:
  1. サイトを開くと、GASがシートに「苦手まとめ」タブを作り、集まった表現(元の表現)を並べます。
  2. まとめ名が空の行を、AIが埋めます(C列に「AI」と入ります)。**B列に自分で書いた行はAIが書き換えません**(気に入らないまとめは、B列を直せばサイトに反映されます)。
  3. AIを使うには、Apps Script の「プロジェクトの設定 → スクリプト プロパティ」に `ANTHROPIC_API_KEY` を追加します(使うモデルは `Code.gs` の `AI_MODEL`)。キーがなくても動き、その時は元の表現が並ぶので、B列を手で埋めればOKです。
  4. AIには「苦手な要素」の短い文言だけが送られます(名前・他の回答は送りません)。
- GASを使わない場合は、`js/content.js` の `dislikeAliases` に `'声が高い': '高い声'` のように書くとまとめられます(AIに「この表現をまとめて」と頼んで、できた対応表を貼る使い方もできます)。
- AIまとめを止めたい時は `config.js` の `ai.group` を `false` に。

## 曲のリンク・曲名の照合(`js/core/lookup.js`)
- 対応しているリンク: YouTube(youtube.com / youtu.be)、Spotify の曲のリンク、Apple Music の曲のリンク(`?i=` つき)。それ以外のリンクや、アルバム・プレイリストのリンクは反映しません。
- 調べる方法: YouTube と Spotify は公式の oEmbed で曲名を取り、iTunes 検索で曲名とアーティスト名をそろえます。Apple Music は iTunes の情報をそのまま使います。文字の曲名は iTunes 検索で、曲名がほぼ一致した時だけ採用します。
- サイトを開いた人のブラウザが直接調べ、結果はそのブラウザに記憶されます(2回目以降は通信しません。見つからなかった結果は3日間おぼえます)。
- **よく聴くアーティスト**: 改行・`,`・`、`・`，`・`;` で区切って1名ずつ検索し、iTunes(なければ MusicBrainz)で実在を確認できた名前だけを結果(アーティストのランキング・要素ごとの表示)に反映します。見つからない名前は反映しません。表記ゆれ(大文字小文字など)は検索で見つかった正式な名前にそろえます。
- **好きな楽曲(リンク欄)**: リンクでなくても、曲名だけ・「曲名 アーティスト名」(空白や `-` `/` 区切り)でも検索します。「曲名 アーティスト名」の形はいろいろな区切り位置を試して積極的に探します。同名の曲が複数ありどれか確実に決まらない時は反映しません(同じ人が「よく聴くアーティスト」に書いた名前で1つに絞れる場合は反映します)。
- **プラットフォーム**: 大文字小文字・全角半角・空白の違いは同じものとして数えます(spotify / SPOTIFY / Spotify → Spotify)。登録済みの名前(`content.js` の `platforms`)を優先し、未登録のものは多く書かれた表記か、大文字小文字が混ざった表記で表示します。
- 通信できない環境では、何も反映されないだけでサイトは普通に動きます。止めたい時は `config.js` の `lookup.enabled` を `false` に。
- 回答が10人に満たない仮データの間は調べません(仮データには調べ済みの形の例が入っています)。

## GASなしで、アンケートをそのままフォームの回答シートに入れる
「あなたの音楽の聴き方を結果に反映」の回答を、Googleフォームの回答として直接送ります。回答は、フォームにつながったスプレッドシートの**空いている次の行に自動で追加**されるので、入力済みの行が書き換わることはありません。GASは不要で、`source.gasUrl` は空のままで構いません。
1. 回答用フォームのページ(…/viewform)を開き、F12 → Console に `tools/get-entries.js` の中身を貼って Enter
2. 出てきた `{ name: 'entry.…', ... }` を `js/config.js` の `survey.form.entries` に貼る(`formId` はすでに入っています)
3. 送信後は、シートを読み直して結果に反映されます(回答が10人以上になると仮データから切り替わります)
注意: この方法では質問文の自動同期(`liveQuestions`)は使えません(GASが必要)。フォームの質問を変えた時は `js/content.js` の `survey.questions` を直し、`entries` を作り直してください。

## アンケート画面(「あなたの音楽の聴き方を結果に反映」)

結果ページ・縦スクロールの下・右上のボタンから、ページに覆いかぶさる形でアンケートが開きます。
**フォームの質問を変えると、アンケート画面も自動で変わります**(`source.gasUrl` を設定している場合)。
アンケート画面を開くたびに、サイトが GAS から Google フォームの最新の質問(質問文・種類・選択肢・必須・ヘルプ文・フォームの説明)を読み、その内容で画面を作ります。
送信時は質問文ごとに答えを送り、GAS が回答シートの「質問文と同じ見出しの列」に書き込みます(全角/半角や空白の違いは無視)。
- 対応する質問: 記述式・段落・ラジオ・チェックボックス・プルダウン・均等目盛り(日付・時刻・表・ファイル・タイトルなしの項目は飛ばします)
- GAS が読むフォームは `Code.gs` の `FORM_ID`(編集画面URLの /d/ と /edit の間)。持ち主がそのフォームの編集権限を持っている必要があります。初回の更新時に承認の確認が出ます
- 読めなかった時(GAS未設定・通信エラー)は、下の `content.js` の質問を使います。`config.js` の `survey.liveQuestions: false` で、フォームの読み取りをやめられます
- 回答の途中でフォームが変わった場合は、その回答を送り終えたあと、次に開く時に反映されます
- 追加した質問は、回答シートには書き込まれますが、グラフ・ランキングには自動では出ません(集計に使う質問は、サイト側の対応が必要です)

フォームを読めない時に使う設問は `content.js` の `survey.questions`(Googleフォームの質問と順番・文言・選択肢をそろえた15問。文言・選択肢はここで直せます)。

送信先は2通り(`config.js`)。上にあるほうが優先されます。
1. **GAS(おすすめ・かんたん)**: `gas/Code.gs` をシートのApps Scriptに貼ってウェブアプリとして公開し、そのURLを `source.gasUrl` に入れる。
   書き込み先は、スプレッドシートの `gid=347610620` のタブ(`Code.gs` の `SHEET_GID`、サイト側は `config.js` の `source.gid`。別のタブにする時は両方を同じ値に)。
   すでに値が入っている行は書き換えません。2行目から見て、**すべてのセルが空の最初の行**に1行ぶん書き込み、空の行がなければ最後の行の次に追加します(一部だけ埋まっている行も飛ばします)。
   列は見出しの言葉で自動対応します(見出しが見つからないタブなら、質問の順番に A 列から書きます)。サイトが次に読み込んだ時にグラフへ反映されます。読み込みと送信の両方がこのURLを使います。
   ※ `Code.gs` を書き換えたら、デプロイ → デプロイを管理 → 編集 → 新バージョン で更新してください。
2. **Googleフォームへ直接送る**: `survey.form.formId`(設定済み)と、各質問の `entry.数字` を `survey.form.entries` に書く。
   `entry.数字` は、フォームの「プレビュー」を開き、ページのソースで `entry.` を検索すると質問ごとに見つかります。
   例: `entries: { name: 'entry.111111111', element: 'entry.222222222', ... }`

どちらも未設定のあいだは、最後の「送信」を押すと「送信先がまだ設定されていません」と表示され、回答は消えません。
送信後、サイトは数秒待って回答を読み直します(10人未満のあいだは仮データのままです)。

## ページを足す・並べ替える

### 文章だけのページ(コード不要)
`js/content.js` の `pages` に1つ書き足し、`js/config.js` の `sceneOrder` にそのidを入れます。
文中の `{{n}}`(回答人数)、`{{top1}}` `{{top1Share}}` などは集計結果に置き換わります。

### 自分で作るページ
1. `js/scenes/_template.js` をコピーして名前を変え、中身を書き換える
2. `index.html` の「ページを足したらここに1行足す」の所に `<script>` を1行足す
3. `js/config.js` の `sceneOrder` に、そのページのidを入れる

並べ替え・削除は `sceneOrder` の並びを変えるだけです。
用意済みで、まだ並べていないページ: `habits`(みんなの聴き方)、`method`(どうやって聞いた?)。

## 線のアニメーション
- 場面が切り替わる時に、線が横切ります(`config.js` の `transition: 'none'` で消せます)。
- 各ページには、止まっている間も動く線(回る輪、放射線、流れる波線、描かれる下線)があります。
  `Site.deco.add(要素, 'wave' など, 'CSSの位置')` で、どのページにも足せます。

## 円グラフの出方を項目ごとに変える
`js/content.js` の各要素の `anim` を書き換えます。
`sweep`(扇が回って出る) / `pop`(ふくらむ) / `fade`(にじむ) / `rise`(下から) / `spin`(回転) / `fly`(外から飛んでくる)。
`animDelay`(開始まで)と `animMs`(かかる時間)もミリ秒で指定できます。

## まとめページ（summary）

`js/content.js` の `summary` で編集します。
- `beats`: 1画面ずつの `lines`（`**強調**`可）と `sub`（補足）。`{mine:true}` の画面は `summary.mine` の文（自分の考え）を表示、`{last:true}` が最後のアンケート誘導。
- `groups.sound`: 「音」に数える要素のID（雰囲気は文脈側）。
- `polar`: 歌詞が「重視」と「聴いていない」両極端の例文（実データがあれば自動で置換）。
- 表示時間は `perCharMs / baseMs / minMs`。クリックで次の画面へ。全体は中央寄せ。
